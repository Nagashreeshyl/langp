# Package Manager

> **Beta** — `lang init`, `install`, and lock files work with an **offline index**. `lang publish` and `lang login` are **not connected** to a remote registry.

## Introduction

The Lang.P **package manager** helps you create projects, declare dependencies, and install packages into a local cache. It uses **`langp.toml`** (manifest) and **`langp.lock`** (pinned versions) — similar in spirit to `package.json` or `Cargo.toml` in other ecosystems.

**Why a package manager:** Reproducible builds, shared libraries, and a standard project layout ([29 — Project Structure](29-project-structure.md)).

**When to use it:** Starting a new app, adding `filesystem` as a dependency, or verifying your toolchain with `lang doctor`.

---

## Syntax

### CLI commands

| Command | Purpose |
|---------|---------|
| `lang init [name]` | Create project with `langp.toml`, `main.lp`, `src/`, `tests/` |
| `lang install [package]` | Resolve deps, write `langp.lock`, download to cache |
| `lang remove <package>` | Remove dependency from manifest and reinstall |
| `lang update` | Refresh lock file from manifest |
| `lang search <query>` | Search offline package index |
| `lang doctor` | Verify `lang`, `langc`, manifest, cache |
| `lang fmt` | Format/check entry file via `lang check` |
| `lang test` | Run `lang check` on every `tests/*.lp` |
| `lang build` | Run `lang check` on entry point |
| `lang publish` | Stub — requires registry (not connected) |
| `lang login` | Stub — requires registry API (not connected) |

Everyday workflow:

```bash
lang init myapp
cd myapp
lang install filesystem
lang check main.lp
lang run main.lp
lang test
lang doctor
```

### langp.toml (manifest)

Created by `lang init`:

```toml
[package]
name = "myapp"
version = "0.1.0"
entry = "main.lp"
description = ""

[dependencies]
filesystem = "0.1"
```

Add dependencies with `lang install filesystem` or edit `[dependencies]` manually.

### langp.lock

Generated by `lang install` — records resolved package versions. Commit this file when sharing projects so everyone gets the same versions.

### Limitations (v0.2.0)

| Limitation | Detail |
|------------|--------|
| Remote registry | Offline index only — no live `langp.dev` |
| `lang publish` / `lang login` | Not connected to a server |
| Git dependencies | Lock records URL; clone/install is minimal |
| Workspaces | Single-level resolution; no monorepos |

See [KNOWN_LIMITATIONS.md](../../KNOWN_LIMITATIONS.md).

## Examples

### Simple — new project

**Learning version:**

```bash
@ Terminal — create and run a new project.
lang init myapp
cd myapp
lang run main.lp
```

**Professional version:**

```bash
lang init myapp && cd myapp && lang run main.lp
```

`main.lp` starter content:

```lp
@ Entry point
print "Hello from Lang.P".
```

### Intermediate — add a dependency

**Learning version:**

```bash
lang install filesystem
```

Then in `main.lp`:

```lp
use filesystem.

write "installed" to "proof.txt".
print filesystem.exists("proof.txt").
delete "proof.txt".
```

**Professional version:**

```lp
use filesystem.
print filesystem.exists("main.lp").
```

### Advanced — doctor and test

**Learning version:**

```bash
@ Verify toolchain and tests folder.
lang doctor
lang test
lang build
```

Create `tests/smoke.lp`:

```lp
@ Smoke test — must pass lang check.
assert true, "sanity".
```

**Professional version:**

```bash
lang doctor && lang test && lang build
```

## Common Mistakes

**Mistake:** Expecting `lang publish` to upload to the internet

```bash
lang publish    @ error: not yet connected
```

**Fix:** Share projects via Git; use local path dependencies until registry ships.

---

**Mistake:** Running package commands outside a project directory

```bash
lang install    @ no langp.toml found
```

**Fix:** Run `lang init` first or `cd` into a project with a manifest.

---

**Mistake:** Deleting `langp.lock` and expecting identical installs without re-running install

**Fix:** Run `lang install` after manifest changes to regenerate the lock file.

---

## Best Practices

- Commit **`langp.toml`** and **`langp.lock`** together.
- Run **`lang doctor`** after installing Lang.P on a new machine.
- Use **`lang test`** in CI before merge ([31 — Testing](31-testing.md)).
- Pin versions in the manifest; let the lock file capture exact resolution.
- Prefer **`lang check`** and **`lang build`** before sharing code ([32 — Best Practices](32-best-practices.md)).

## Summary

The **beta** package manager provides **`lang init`**, **`install`**, **`remove`**, **`update`**, **`search`**, **`doctor`**, **`fmt`**, **`test`**, and **`build`**. Manifests live in **`langp.toml`**; resolved deps in **`langp.lock`**. **`publish`** and **`login`** are stubs until a remote registry connects.
